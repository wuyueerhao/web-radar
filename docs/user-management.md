# 用户、权限与按创建者统计

两种部署共享此功能源码，各自使用自己的数据库；角色配置和业务数据不会自动在 Cloudflare 与服务器之间复制。

## 账号和角色

登录仍由 Product Radar 统一账号服务验证。首次登录登记姓名、邮箱、工作区和账号 ID；既有网站创建者迁移为待补齐资料的条目。Web Radar 不创建独立密码。超级管理员角色由统一账号服务管理，不能通过本地 API 授予。

- 超级管理员：全平台用户和业务数据；平台配置。
- 工作区管理员：本工作区用户角色、停用/启用；工作区业务数据及营销服务商配置。
- 数据主管：只读查看本工作区所有成员的网站、邮件活动及站内信任务。
- 业务成员：创建和操作自己的项目、邮件活动、站内信任务；联系人、模板与可用发送通道仍为工作区共享资源。
- 只读成员：只读查看自己的业务记录，不能创建、修改、发布或发送。

修改权限不能针对自己或超级管理员。修改使用版本号防止覆盖并发操作，并保留审计记录。停用删除该账号在对应工作区的会话；权限在后续请求中重新检查。用户数据保留。

`wr_members` 中的本地角色覆盖默认工作区角色，但不能提升为超级管理员。默认值继承统一账号服务的当前工作区管理员/成员角色；本地角色为空时会跟随上游角色变化。

## 数据归属

网站始终使用 `projects.owner_id`；新邮件活动和站内信任务使用服务端身份写入 `created_by`，忽略客户端伪造创建者字段。现有 EDM 数据只记录工作区，没有可恢复的个人创建者，保持 NULL 并标记“历史共享数据”，管理员/数据主管可查，不能归到某个人以凑统计。

左侧 `用户管理` 仅向管理员开放，包含角色、访问状态和权限操作记录。`业务数据` 向管理员及数据主管开放，包含用户汇总、网站项目、EDM 邮件和站内信；用户列表的“查看业务数据”会跳转并保留用户筛选。

后台支持姓名/邮箱/ID 搜索、分页、按用户查看三类业务，以及创建时间、状态、邮件互动与站内信结果。超级管理员可跨工作区；数据主管和工作区管理员始终受到工作区边界限制。

## 邮件记录的范围

已发送、送达、打开和点击来自系统活动与收件人记录及服务商回执。Cloudflare 域名 DNS 托管、Email Routing 转发配置本身不能读取收件邮箱内的历史邮件。回复读取需要实际收件邮箱的授权，或在邮件进入时通过 Email Worker 接收并转存。没有接入回复收集时，回复数 0 不能解释为没有收到回复。

## 部署

先备份业务库，再执行 `0010_user_management.sql`，然后发布应用。新列对旧版应用兼容，回滚应用时保留迁移，不删除归属与权限记录。Cloudflare 使用 D1 迁移；服务器使用同一迁移文件。不要将 Cloudflare 库覆盖服务器库，反之亦然。
